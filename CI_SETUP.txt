HIVE-UI CI SETUP REQUIREMENTS
=============================

New repository/environment secrets required by this CI update: NONE.

The new security workflow uses GitHub's automatically provided GITHUB_TOKEN for OpenSSF Scorecard. Do not create a PAT for Scorecard.

Existing HIVE-UI secrets used by pre-existing workflows are unchanged and are not introduced by this CI update:
- OPS_ALERT_WEBHOOK_URL
- OPS_ALERT_WEBHOOK_TOKEN
- HIVE_UI_ACCESS_KEY
- ECOSYSTEM_SMOKE_DISPATCH_TOKEN

Existing repository variables used by pre-existing workflows are unchanged:
- HIVE_UI_E2E_BASE_URL (optional; production URL fallback already exists)
- ECOSYSTEM_SMOKE_REPOSITORY (optional; owner/MAST fallback already exists)

DEPENDENCY / LOCKFILE POLICY
----------------------------
- Dependabot is retained for repository/supply-chain posture but both npm and GitHub Actions entries now use open-pull-requests-limit: 0.
- Mend Renovate is the dependency-update owner.
- Renovate runs in the Sunday 03:00-04:00 Europe/London window.
- Renovate lockFileMaintenance is enabled and may automerge only after required CI permits the PR to merge.
- npm patch/minor updates may automerge after required CI passes.
- npm major updates remain manual.
- GitHub Actions updates remain manual because Actions execute CI code.
- package.json and package-lock.json remain synchronised in the same Renovate PR. Existing npm ci and verify:lock checks fail inconsistent lockfiles.
- The deployed-integration recovery workflow now recognises merged Renovate PRs instead of Dependabot PRs before opening a validated revert PR.

SCHEDULE
--------
- CodeQL Advanced: Sunday 03:00 UTC.
- Security/repository-quality workflow: Sunday 03:00 UTC, plus normal PR/push execution.
- Renovate: Sunday 03:00-04:00 Europe/London.
- Normal CI still runs immediately on pushes and pull requests.

CI TOOLS ADDED
--------------
- Trivy 0.74.0: direct pinned CLI; filesystem dependency and misconfiguration scanning.
- Gitleaks 8.30.1: direct pinned CLI; full-history scan with a redacted diagnostic artifact if a finding occurs.
- actionlint 1.7.12: direct pinned binary.
- Lychee 0.24.2: direct pinned binary for HIVE-UI documentation/link integrity.
- OpenSSF Scorecard 5.5.0: direct pinned CLI build/run.
- Existing CodeQL Advanced is retained and scheduled consistently.
- Hadolint is not installed because HIVE-UI contains no Dockerfile.
- ShellCheck is not installed because HIVE-UI contains no meaningful standalone shell scripts.

PRE-EMPTIVE TOOLCHAIN CORRECTION
--------------------------------
package.json and package-lock.json require npm 10.9.9, while existing workflows asserted npm 10.9.4. CI and deployed-integration now explicitly install npm 10.9.9 after Node setup before asserting the toolchain. This prevents the stale npm assertion failure already encountered during the IRS rollout.

GITLEAKS DIAGNOSTICS
--------------------
The Gitleaks job produces a redacted JSON artifact on findings before failing the job. This preserves rule/file/commit/line/fingerprint metadata without printing the secret, allowing exact fingerprint exceptions only when a finding is proven synthetic.

OWASP ZAP
---------
ZAP remains an ecosystem-level monthly DAST control rather than a per-PR HIVE-UI repository check. No ZAP secret is introduced by this update.

Cloudflare production build toolchain
- Cloudflare's build environment must not infer/install npm from package.json. The production build log on 2026-09-26 detected npm 12.1.0 and failed during tool installation before dependency installation or the application build began.
- Node remains repository-pinned to 22.22.0 via .node-version and package.json engines.node.
- The npm packageManager and engines.npm declarations are intentionally omitted from package.json so Cloudflare uses the npm bundled with the pinned Node runtime instead of attempting a separate npm tool installation.
- GitHub CI remains deterministic: its workflows explicitly install and assert npm 10.9.9 before npm ci. Do not re-add packageManager or engines.npm without first validating Cloudflare's build-tool detection.
