HIVE-UI CI SETUP REQUIREMENTS
=============================

New repository/environment secrets required by this CI update: NONE.

The new security workflow uses GitHub's automatically provided GITHUB_TOKEN for OpenSSF Scorecard. Do not create a PAT for Scorecard.

Existing HIVE-UI secrets used by pre-existing workflows are unchanged and are not introduced by this CI update:
- OPS_ALERT_WEBHOOK_URL
- OPS_ALERT_WEBHOOK_TOKEN
- HIVE_UI_ACCESS_KEY
- ECOSYSTEM_SMOKE_DISPATCH_TOKEN

Existing repository variables used by pre-existing workflows are unchanged:
- HIVE_UI_E2E_BASE_URL (optional; production URL fallback already exists)
- ECOSYSTEM_SMOKE_REPOSITORY (optional; owner/MAST fallback already exists)

DEPENDENCY / LOCKFILE POLICY
----------------------------
- Dependabot is retained for repository/supply-chain posture but both npm and GitHub Actions entries now use open-pull-requests-limit: 0.
- Mend Renovate is the dependency-update owner.
- Renovate runs in the Saturday 21:30-23:59 Europe/London window.
- Renovate lockFileMaintenance is enabled and may automerge only after required CI permits the PR to merge.
- npm patch/minor updates may automerge after required CI passes.
- npm major updates remain manual.
- GitHub Actions updates remain manual because Actions execute CI code.
- package.json and package-lock.json remain synchronised in the same Renovate PR. Existing npm ci and verify:lock checks fail inconsistent lockfiles.
- The deployed-integration recovery workflow now recognises merged Renovate PRs instead of Dependabot PRs before opening a validated revert PR.

SCHEDULE
--------
- CodeQL Advanced: Saturday 21:30 UTC.
- Security/repository-quality workflow: Saturday 21:30 UTC, plus normal PR/push execution.
- Renovate: Saturday 21:30-23:59 Europe/London.
- Normal CI still runs immediately on pushes and pull requests.

PRE-EMPTIVE TOOLCHAIN CORRECTION
--------------------------------
package.json and package-lock.json require npm 10.9.9, while existing workflows asserted npm 10.9.4. CI and deployed-integration now explicitly install npm 10.9.9 after Node setup before asserting the toolchain. This prevents the stale npm assertion failure already encountered during the IRS rollout.

GITLEAKS DIAGNOSTICS
--------------------
The Gitleaks job produces a redacted JSON artifact on findings before failing the job. This preserves rule/file/commit/line/fingerprint metadata without printing the secret, allowing exact fingerprint exceptions only when a finding is proven synthetic.

OWASP ZAP
---------
ZAP remains an ecosystem-level monthly DAST control rather than a per-PR HIVE-UI repository check. No ZAP secret is introduced by this update.

Cloudflare production build toolchain
- Cloudflare's build environment must not infer/install npm from package.json. The production build log on 2026-09-26 detected npm 12.1.0 and failed during tool installation before dependency installation or the application build began.
- Node remains repository-pinned to 22.22.0 via .node-version and package.json engines.node.
- The npm packageManager and engines.npm declarations are intentionally omitted from package.json so Cloudflare uses the npm bundled with the pinned Node runtime instead of attempting a separate npm tool installation.
- GitHub CI remains deterministic: its workflows explicitly install and assert npm 10.9.9 before npm ci. Do not re-add packageManager or engines.npm without first validating Cloudflare's build-tool detection.

AUTONOMOUS PROVING-GROUP SETUP
- Scheduled window: Saturday 21:30 UTC; 2.5 hours reserved before the next repository starts.
- KiloConnect + Kilo Code Bot: authorise both GitHub integrations for this repository. Failed default-branch CI/deployment-watch runs create one deduplicated repair PR and invoke @kilocode-bot in PR context.
- Kilo may prepare dependency-manifest/lockfile/build fixes when evidence requires them, but all changes remain PR-only and must pass existing gates.
- Mergify config handles explicit superseded/obsolete PR cleanup only; it is not the merge authority.
- GitHub native branch/ruleset protections remain authoritative. Native Merge Queue can be enabled after required checks are confirmed stable.
- R2 Council ingestion/publishing is deferred to the HIVE Council implementation; no R2 credentials are introduced by this phase.
- Codecov and OWASP ZAP are intentionally NOT enabled.

- GitHub Actions must be allowed to create pull requests in repository Actions settings for the autonomous repair-PR workflow.
- Enable Kilo Code Reviews for this repository and enable REVIEW.md guidance in the Kilo Code Reviews configuration.
- Kilo Code Reviewer is review-only; the repair PR also invokes @kilocode-bot in PR context for implementation. Bot-generated PR review behaviour must be verified in Kilo settings because Kilo documents bot-created PRs as ignored by default by automatic Code Reviews.

AUTONOMOUS REPAIR AUTHENTICATION
- Required repository variable: AUTONOMY_REPAIR_APP_ID
- Required repository secret: the GitHub App private-key secret referenced by `.github/workflows/autonomous-repair.yml`
- The installed Autonomy Repair GitHub App needs Contents read/write, Pull requests read/write and Issues read/write for this repository.
- Repair PRs are created with the GitHub App installation token, not GITHUB_TOKEN, so pull_request workflows start without the manual approval loop applied to workflow-created GITHUB_TOKEN PRs.
- Mergify auto-merges an autonomy:repair PR only after the Autonomous repair marker gate succeeds and no active checks remain failed or pending. Kilo Code Review remains useful when it runs, but is not a mandatory named check because bot-generated PR review behaviour can vary. GitHub branch protection/rulesets remain authoritative.
- The old Renovate-specific deployment-revert PR path has been removed where present so a failed deployment produces one repair path rather than competing recovery PRs.

AUTONOMOUS MERGE SETTINGS
- Kilo Code Review should remain enabled for repository pull requests with REVIEW.md guidance, but autonomous merging does not depend on that named check being present.
- Mergify must have repository access. `.mergify.yml` auto-merges only validated `autonomy:repair` PRs after the repair-marker gate succeeds and all active checks are clear.
- Protect `main` with the repository's normal required checks. At minimum, the aggregate release/CI gate, the Autonomous repair marker gate, the repository security checks, and Kilo/Socket checks that are configured as merge gates should be required.
- Keep GitHub's workflow-approval security policy enabled; App-created repair PRs no longer depend on the workflow `GITHUB_TOKEN`.
- Enable GitHub's automatic deletion of head branches after merge to keep autonomous repair branches tidy.
